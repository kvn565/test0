-----------

le projet Django, en creant des factures exactement comme si elles avaient

calcul existant du projet.

Resultat attendu : les montants en base reproduisent le fichier
    P.T HTTC + TVA + PF = PT TTC

perturber l'application en ligne (changement de schema evite).

4. LE FICHIER EXCEL ATTENDU
---------------------------
- Format .xlsx, feuille "Table 1" (sinon 1ere feuille).
- En-tete DETECTE AUTOMATIQUEMENT : ligne contenant a la fois "numero" et un "client".
- Intitules non sensibles a la casse/accents, espaces normalises.

Colonnes OBLIGATOIRES :
    Numero, Type de factures, Produit, Qtes, P.T HTTC, TVA, PT TTC, Date, Client

Colonnes OPTIONNELLES :
    Type de paiement, Status, Unite, P.U HTTC, TC, PF, OTT, TSCE,
    NIF du Client, Devise, Auteur

- Lignes vides et lignes "TOTAL..." ignorees. Lignes de statut non "valide/valides" ignorees.
- Si un Produit / Client / Taux / Categorie n'existe pas -> CREATION AUTOMATIQUE.


5. REGLE DE CALCUL (POINT CRITIQUE - "Option B")
-----------------------------------------------
Pour chaque ligne du fichier :

    montant HT enregistre = P.T HTTC                   (la TC est DEJA incluse)
    taux TVA              = TVA / P.T HTTC x 100
    taux PFL              = PF  / P.T HTTC x 100
    prix unitaire (HT)    = P.T HTTC / Qtes
    prix TVAC (ligne)     = prix_unitaire_ht x (1 + taux_TVA/100)

Consequences voulues :
- La TC n'est JAMAIS appliquee une 2e fois (elle est fondue dans le HT) => taux_tc = 0.
- Le taux TVA est conserve LIGNE PAR LIGNE (0 %, 10 % ou 18 %), meme si le produit a un
  autre taux principal. Le taux domine par produit ne sert qu'a la config produit/OBR.
- Cas particulier verifie : FN/25/2025 (Hebergement) -> TVA = 0, TTC = 75999.95 exact.

Pourquoi ce choix : la TVA du fichier est calculee sur P.T HTTC ; pour reproduire
P.T HTTC + TVA + PF = PT TTC a l'identique, il faut donc enregistrer P.T HTTC comme base HT.


6. LOGIQUE DU MOTEUR (superadmin/importation.py)
------------------------------------------------
Fonctions cles (fichier de 790 lignes) :

- parse_fichier(path)          -> lit l'Excel, construit invoices, produits_rates,
                                  assujetti, errors, warnings. Ne touche pas la base.
- analyser_fichier(path, societe, mode)  -> PREVIEW : compare aux numeros/clients/produits
                                  existants, renvoie doublons, nouveaux clients, nouveaux
                                  produits, apercu. N'ECRIT RIEN.
- importer_fichier(path, societe, mode, user) -> ECRITURE reelle, transaction.atomic()
                                  par facture, idempotent (un numero deja en base est
                                  skipped_existing).

Helpers : _norm, _clean, _to_decimal (gere virgule/point, espaces, espace insecable),
_parse_datetime, _index, _taux, _dominer, _read_rows (openpyxl read_only),
_get_or_create_*, _activer_assujettissement, _resoudre_categorie, _creer_facture,
_creer_ligne.

!!! PIEGE MAJEUR - LigneFacture.save() force le taux du produit !!!
LigneFacture.save() reapplique produit.taux_tva et recalcule HT/TVA depuis prix_vente_tvac.
Pour preserver le taux REEL de la ligne, _creer_ligne fait :

    ligne_obj.save()                                    # passage par le moteur du projet
    LigneFacture.objects.filter(pk=ligne_obj.pk).update(  # override en DB
        taux_tva=taux_tva, prix_vente_tvac=prix_tvac, prix_unitaire_ht=pu_ht,
    )
    # puis on realigne l'instance en memoire et on purge les caches de proprietes

Ne pas oublier facture.recalculer_totaux() apres les lignes.

Facture creee :
    statut_obr='ENVOYE', applique_tva=True, invoice_identifier via _build_identifier,
    date_envoi_obr / obr_registered_date = date de la facture,
    message_obr = "Importe depuis un fichier Excel".

Societe :
    _activer_assujettissement active assujeti_tva (et tc/pfl si detectes) selon le fichier.
    assujetti est calcule LIGNE PAR LIGNE dans parse_fichier.


7. FLUX DE LA VUE (2 ETAPES - ne pas simplifier)
------------------------------------------------
1) GET  -> formulaire (societe + fichier).
2) POST action=preview -> analyser_fichier : affiche resultats + bouton
   "Confirmer l'importation".
3) POST action=import  -> importer_fichier : ecrit en base, puis supprime le fichier
   temporaire importe dans MEDIA_ROOT/importations/.

Le fichier uploade est stocke temporairement sous :
    import_{YYYYmmdd_HHMMSS}_{user_pk}.xlsx
(controle par prefixe/suffixe avant import).

UX : le bouton d'import N'APPARAIT QU'APRES L'ANALYSE. Le 1er bouton visible est
"Analyser le fichier". C'est volontaire (securite : preview avant ecriture).

Mode : PRODUCTION uniquement (mode = True code en dur, selecteur retire).
